# OCR Distillation Trajectory Sampling

Implement the trajectory sampler and the transition-with-log-probability step that a fixed
on-policy distillation trainer uses to teach Stable Diffusion 3.5 Medium to render the text a
prompt asks for. Maximize the mean OCR reward of the trained student's held-out images after the
fixed eight-update training budget. A valid submission completes the eight verified updates with
finite consumed values and satisfies the sampling and replay contracts below.

## Task

Flow-OPD (paper: *Flow-OPD: On-Policy Distillation for Flow Matching Models*) trains a LoRA
adapter on SD3.5 Medium, a flow-matching model that evolves noise through latents and decodes the
last one to pixels. In the retained single-teacher `kl_only` path an OCR-specialized teacher
supervises states generated by the current student; the loss also penalizes distance to the base
model; rollout OCR rewards pass through the retained prompt statistics and sample filtering; and
the EMA of the student's weights is evaluated at the endpoint. The bodies of `pipeline_with_logprob`
and `sde_step_with_logprob` are removed (`NotImplementedError`); supply both.

## Interface

The signatures are in the two files; keep `@torch.no_grad()` on `pipeline_with_logprob`. Rollout,
endpoint generation and optimization replay share one scheduler, timestep, shape and
noise-coefficient convention.

```python
pipeline_with_logprob(self, ...)   # self: the SD3 pipeline
sde_step_with_logprob(self, model_output, timestep, sample, noise_level=0.7, prev_sample=None,
                      generator=None, sde_type="sde", return_sqrt_dt=False)   # self: the scheduler
```

**Sampler.** Use the supplied embeddings, guidance, scheduler, device, initial `latents` and
`generator` (list). The trainer passes dimensions, steps, guidance, noise level, embeddings and
`output_type="pt"`; training uses `generator=None`, evaluation initial latents and seeded
generators. Return `(images, states, log_probs)`, plus `means` if `return_prev_sample_mean=True`
(`B` images, `T` transitions): `images` RGB `[B, 3, 512, 512]` in `[0, 1]`; `states` `T+1`
tensors `[B, 16, 64, 64]` from the initial latent; `log_probs` `T` tensors `[B]` (entry `i`
scores `states[i+1]` given `states[i]`); `means` `T` state-shaped tensors.

**Step.** The trainer passes `sde_type="sde"`; replay passes float32 tensors and one timestep per
example. Return `(next_state, log_prob, mean, noise_coefficient)`, plus `sqrt(-dt)` if
`return_sqrt_dt`; `log_prob` is `[B]`, the others broadcast like `sample`. Without `prev_sample`,
sample with `generator`; with it, return it unchanged and consume no randomness. With
`dt = sigma_next - sigma` (the scheduler's noise levels), the standard deviation is
`noise_coefficient * sqrt(-dt)` and

```text
log_prob[b] = mean over non-batch elements of
              -0.5 * ((next_state - mean) / (noise_coefficient * sqrt(-dt)))^2
              - log(noise_coefficient * sqrt(-dt)) - 0.5 * log(2*pi)
```

The next state is held fixed when differentiating; `mean` and `log_prob` keep finite gradients in
`model_output`; the KL uses `noise_coefficient**2` without the time factor. At `noise_level=0` the
step is deterministic: a next state equal to the mean has log mass `0`, any other `-inf`; sampled
evaluation trajectories have zero log-probability entries.

```python
images, states, log_probs, means = pipeline_with_logprob(
    pipe, prompt=[prompt, prompt], height=512, width=512, num_inference_steps=10,
    guidance_scale=4.5, noise_level=0.7, output_type='pt', return_prev_sample_mean=True)
    # images (2, 3, 512, 512); 11 states (2, 16, 64, 64); 10 log_probs (2,); 10 means
next_state, lp, mean, coefficient, sqrt_dt = sde_step_with_logprob(
    pipe.scheduler, model_output, timestep, states[0],     # timestep.shape == (2,)
    noise_level=0.7, prev_sample=states[1], return_sqrt_dt=True)
    # next_state is exactly states[1]; lp (2,)
```

The judge runs `bash scripts/single_node/sd3_opd_example.sh`; its `accelerate launch` line is
checked exactly and run as one process on one H100.

## Correctness

The score is 0 when: the patch is rejected; the build or import fails; a body is missing; the run
crashes, times out (900-second scientific profile within the evaluation timeout) or generates
incomplete output; a required update is missing or skipped; a consumed state, loss or gradient is
non-finite; or a transition or checkpoint check fails. Checks: ordered trajectory and batch
shapes, replay equality and the density formula with absolute tolerance `1.9073486328125e-06`
and relative tolerance `0.0`; consumed training transitions need positive variance (no mixed zero
and positive variance in one transition); endpoint images, initial latents and rewards must
agree after reloading the saved EMA adapter. Cached images, substituted models, invented latents,
teacher images, extra held-out training, looking up the graded prompts and seeds that reach the
trainer process, or inspecting the evaluator are invalid.

## Workload

One workload is one generated 512×512 image for one prompt and one evaluation seed, from the
endpoint of one eight-update training run (seed `260508063`; 10 rollout transitions, noise `0.7`,
guidance `4.5`, `beta = 0.04`, 9 trained transitions, `kl_scale=-1`, bf16, 2 samples per prompt,
batch 4, 2 sampling batches per epoch; AdamW lr `3e-4`, betas `(0.9, 0.999)`, weight decay
`1e-4`, eps `1e-8`, max grad norm `1.0`; LoRA rank 32, alpha 64). Endpoint images use 40
transitions at noise `0`, batch 1.

| suite | workloads |
|---|---|
| train: development (scored) + train-grading (criterion) | 8 + 8, one run |
| final | 8, a fresh run |

Each suite has four normalized-target groups (stratified by target length, word count, context
length, digits and character set), one prompt each and two seeds per prompt; the suites share no
prompt or target. Training prompts are the 17,307 eligible lines in
`/workspace/repo/frontier_data/train.txt` (no paired images); a prompt's target is its first
double-quoted text. `/workspace/repo/frontier_data/test.txt` and
`/workspace/repo/frontier_profile.json` hold the public evaluation lines, seeds and settings.
Evaluation latents come from the frozen seeds, independent of training randomness. Time is not
scored.

## Scoring

```text
score = 100 * (1/N) * sum over the scored suite of ocr_reward(w)      (0 if any workload is invalid)
ocr_reward = 1 - d / len(t),  d = 0 if t is a substring of s, else min(Levenshtein(s, t), len(t))
```

`t` is the target and `s` the concatenated OCR text with positive confidence, both lowercased
with ASCII spaces removed; an OCR exception gives 0; rewards are not rounded. The scored suite is
the 8 development workloads in train and the 8 final workloads in final.
Anchors: the starter scores 0; the maximum is 100.

**Beats the reference** requires, on every graded workload, an OCR reward strictly higher than
the reference's where the reference is below 1, and equal to 1 where it is 1 (unrounded, no
tolerance; other workloads cannot compensate). It does not change the score.

## Running locally

On a GPU runner (prefix with `/opt/frontier/task-runtime`, see `/frontier/task/README.md`):
`bash /workspace/repo/frontier-build.sh` checks offline imports and syntax;
`bash /workspace/repo/frontier-bench.sh --profile /workspace/repo/frontier_profile.json --output
/workspace/bench-out` trains and evaluates on the public profile. That profile is a calibration
profile: it does not run the judge's transition and replay checks.
