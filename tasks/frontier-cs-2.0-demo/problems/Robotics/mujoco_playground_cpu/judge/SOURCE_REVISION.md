# Go1 joystick policy training: source revision 2026-10-11

Hand-authored replacement of the previous `mujoco_playground_cpu`
revision `g1-agent5h`, which graded bit-exact reconstruction of removed Go1
reward code on CPU. The problem id is kept because the importer replaces a task
by its id; the id's `_cpu` suffix is historical: this revision trains and
verifies on an H100. The previous revision's tree, tests and published images
remain in Git history and on the registry.

Publication status. Immutable images for the five roles (agent, verifier,
datasets, agent GPU, verifier GPU) are published under `docker.io/joyemang33`
with source-bound tags and pinned by digest in `config/task-catalog.json`,
which is the authority for the digests; this file is part of the source
identity and therefore names neither the digests nor the identity. The author
calibrated on a Modal H100 by running this evaluator in an image built from
`verifier-gpu/Dockerfile` without its SSH-bootstrap stage (development suite
1,128 s, final suite 5,728 s; see `judge/readme`, Calibration status). Native
Driver qualification with the published images (reference train and final) is
pending and will be run by the transfer line.

`google-deepmind/mujoco_playground` at

  previous revision of this task and verified on 2026-10-10 to be
  byte-identical to `unitree_go1/` (10 files) of
  `google-deepmind/mujoco_menagerie` at
  `14ceccf557cc47240202f2354d684eca58ff8de4`, the commit
  `mjx_env.MENAGERIE_COMMIT_SHA` pins. Only Go1 assets are present,
  so environments of other robots cannot be loaded.

The previous revision's `judge/harbor/app` with its `reference.patch` applied
was a 109-file subset of this tree (every shared file verified byte-identical
at source commit `eca1271e`); it lacked `mujoco_playground/config/` and
`learning/`, which this statement cites, so the full tree is used instead.

The upstream `.gitignore` in this tree ignores `mujoco_menagerie`, so the
vendored assets are tracked in the source repository with `git add -f`. In a
solver's workspace the same rule keeps them out of the baseline commit and out
of every patch.

## Execution boundary

See the module docstring of `judge_deps/runtime.py`. In short: submitted
Python runs only in a candidate training child; the policy crosses to the
evaluation as a `jax.export` (StableHLO) artifact; the evaluation process
imports the environment only from a pristine tree that the runner re-hashes
against `judge_deps/source.json` before every trusted launch.

`judge_deps/source.json`, `upstream.lock.json`, the dataset hashes in
`policy.json` and the policy blocks in `agent-base/frontier/task/bin/README.md`
are generated by `task_tests/mujoco_playground_cpu/regenerate_bindings.py`.
